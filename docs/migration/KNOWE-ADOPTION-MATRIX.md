## B. Decision principles

1. Knowe is a reference product, not a base framework.
2. Hospital Workspace is server-authoritative.
3. Chat is a projection and collaboration surface, not a business database.
4. Cards execute typed commands; domain services own business state.
5. Models may propose; deterministic services and Harness decide.
6. User adjudication and authoritative service state override model inference.
7. Security boundaries take precedence over local-first convenience.
8. No mechanism is adopted without a Hospital Workspace landing component, phase and acceptance condition.
9. Design reference does not authorize code copying.
10. MIT attribution applies only if source code is copied; no code is copied in HW00-05.

Decision values are `ADOPT_CONCEPT`, `ADAPT`, `REFERENCE_ONLY`, `EXCLUDE`, `DEFER`. Status values are only `PLANNED`, `NOT_AUTHORIZED`, `EXCLUDED`.

## E. Required mappings

1. Group conversation -> Capability Space -> Work Item Thread -> Activity Timeline and Chat/Card/Canvas; chat is never authority.
2. Coordinator/Worker -> server Agent Gateway; no client runtime or arbitrary local execution.
3. Harness -> deterministic WorkItem/Harness; model cannot complete, approve, cancel or mutate.
4. Approval -> typed Card, command, Authz, audit and event confirmation; optimistic UI cannot advance state.
5. Handoff -> auditable WorkItem-bound record; text cannot grant permission or state.
6. Replay -> Collaboration, Outbox, sequence, idempotency and cursor rebuild; JSONL/local history is not central truth.
7. Knowledge -> governed Knowledge Service; Agent output is a recommendation until publication.
8. Artifacts -> authorized references and scoped storage; no arbitrary filesystem.
9. Desktop -> Tauri/WebView2 surfaces; no Electron/Node privilege or remote native access.
10. Provider/tools -> Agent Gateway server-side provider-adapter (Model Gateway function) and typed tool-registry/execution (Tool Gateway function); no client keys, prose pseudo-calls or user endpoints.
