# ADR-0001：使用独立公共绿地仓库

## 背景

Hospital Workspace 需要从人员、事件、任务、工作项和上下文重新组织医院内网入口。直接继承旧仓库历史会把旧页面、阶段脚本、迁移、证据和交叉依赖带入新产品，同时可能公开环境敏感信息。

## 决策

创建新的公共 `peterkis/hospital-workspace` monorepo，并从单一干净初始提交开始：

- 不复制任何旧 `.git` 历史、Issue、PR 或 Actions 日志；
- 不把其他仓库作为 Submodule、运行依赖或 CI 前置；
- 医院私有配置全部置于 `.gitignore` 覆盖的本地路径或部署环境；
- 可选旧源缺失时，所有阶段按目标架构和契约重新实现；
- 可选旧源存在时，也只能按白名单、固定 commit 和迁移收据选择性采用。

## 后果

增加一次性绿地建设成本，换取一个可公开审查、可强制 Ruleset、单一活动且长期认知负担更低的仓库。

## 回滚

在 G00 Clean Foundation 通过前，可删除并重新创建新仓；不得通过恢复旧历史来绕过公开数据边界。
